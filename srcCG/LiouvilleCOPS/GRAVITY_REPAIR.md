# Gravity orientation repair and validation

Implemented 2026-10-19. See `HEAL-corruption.md` for the defect evidence.
This repair changes orientation handling and cache provenance; it does not
change homogeneous density, offset, SPICE rotation, or cliff definitions.

## Independent audit

`tools/gravity_topology.py::require_outward_closed_body` checks finite vertices,
integer in-range indices, nonzero finite triangle areas, unique triangles, no
unreferenced vertices, exactly two incident faces per edge, opposing directed
edges, one connected face component, manifold vertex links, Euler characteristic
2, and positive finite signed volume. No vertex merging or winding repair occurs.
Volume is calculated about a translated origin to reduce cancellation. Edge
sorting and sparse connectivity replace the package's quadratic ray test.

The vertex-link test matters: edge incidence and Euler alone do not generally
exclude pinched surfaces. Face corners are connected across shared edges, and
each mesh vertex must have exactly one connected cyclic link. The accepted
topology is one closed genus-zero body, appropriate to this SHAP5 application.
The audit does **not** establish absence of geometric self-intersections; mesh
provenance and independent geometric validation remain required for other inputs.

Both `effective_slope` and `validate_gravity_resolution` now audit and then use
`PolyhedronIntegrity.DISABLE`. The builder also audits before accepting a cache.
The package cannot flip faces during construction. Metadata records the policy,
audit, exact vertex/face-order hashes, package version/commit and package binary
identity. Nonfinite offset/resolution results are rejected.

## Cache incompatibility and products

`gravity_cache.ALGORITHM` is now
`homogeneous_polyhedron_self_gravity_at_outward_offset_v2_disable_after_topology_audit`.
Definitions also include the orientation policy
`DISABLE after independent outward closed manifold audit v1`.
Old HEAL definitions therefore fail exact comparison even with matching source
mesh hashes. On reuse, the builder additionally requires matching topology and
orientation metadata. A filename change alone is never sufficient validation.

Previously calculated HEAL self-gravity and cliff masks require quarantine and
regeneration. The earlier 100k resolution rejection must be re-evaluated with the
corrected code; it cannot be justified by the corrupted slope comparison.
Geometry-only NG visibility is unaffected. Bundle consumers must gate cliff
selection on corrected provenance (the shared template-loader integration does
this separately).

Each newly generated cliff template reports area fraction and the original
zero-based facet indices within 1e-6 degrees of its threshold. This makes tiny
classification differences visible during CPU/GPU comparisons.

## Verification completed

The new `tests/test_gravity_topology.py` covers invalid/open/inward/mixed-winding
and disconnected inputs; scale/translation invariance of topology and volume;
cache incompatibility; both production gravity-construction paths; gravity
direction and density scaling; radius-1000/radius-1 similarity; and reproduction
of the pinned package's HEAL corruption. Our deterministic 1280-triangle sphere
had 606 faces changed by HEAL at radius 1000 m. The exact count is not portable,
so the test requires occurrence of corruption rather than that particular count.

The real SHAP5 788k audit passed: 393879 vertices, 787754 triangles, one body,
manifold vertex links, Euler 2, signed volume 18758808441.830097 m³. Reading and
auditing took about 8.4 seconds on the development host.

All eight new tests passed with the persistent polyhedral-gravity 3.3 package,
including eight evenly distributed C00 target comparisons at vector-relative
error <=1e-12. This small reference test is a development check, not full-field
production acceptance. No full gravity field was regenerated by these tests.

Run the quick suite with:

```bash
PYTHONPATH=/data/vtenishe/rosetta_data_end_of_mission_cops/liouville_cops_polyhedral_gravity \
python3 -m unittest discover -s tests -p test_gravity_topology.py -v
```

To include C00 (default eight targets), additionally set
`COPS_GRAVITY_REFERENCE` to the absolute path of `gravity_788k.npz` beside its
`gravity_fixtures.json`. Set `COPS_GRAVITY_REFERENCE_TARGETS=832` for all recorded
offset targets. This opt-in avoids making routine tests depend on external data
or several minutes of reference evaluation.

## Remaining production acceptance

Regenerate corrected fields using the normal builder or import independently
validated CUDA results through an explicit provenance-preserving conversion.
The current builder does not implement that import. Compare all 832 C00 targets
and the validated CUDA full field, inspect threshold-near facets, review gravity
direction and slope distributions, and repeat the offset-halving check.
Plausible slope statistics and agreement between two offsets alone do not prove
correct orientation. Requested CPU resources are 36 threads; the package uses
TBB, so `OMP_NUM_THREADS` alone is not evidence of its actual thread limit.
