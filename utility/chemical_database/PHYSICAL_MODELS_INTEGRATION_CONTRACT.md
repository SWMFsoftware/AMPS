# Shared physical-source/model integration contract — 2026-11-19

The user approved incorporating the researched measurements and community
approximations into the application-independent chemical database. This is an
additive immutable r3 publication; r1/r2, their locks and canonical originals

## Inventory, entry points and configuration

Existing `source_inventory.inventory`, strict `source_packets.load_packets`,
`build_database`, installed Python `Database`/CLI and C++ `Catalogue` provide
native/CSV source access. Original rate services are already shared C++17.
The current explicit packet interface allows provider-specific cleared data,
native parent/recipe pins and metadata-only holds. Runtime is offline.

New native recipes will prepare CHIANTI O I level/radiative tables, literal
Apollo source tokens, original workbook cells and the published observation/
model columns. Missing units or mixed roles cannot become inferred science
columns. Every original, empty token, signed value, source marker, formula/cache
and measured/derived/model distinction remains available. Original source/recipe
and native licence identities are archived with the release. Named CHIANTI and
publisher-specific rights are separately reviewed; existing holds remain.

## Reusable model definitions and kernels

Add an explicit `--include-model-definitions` publication option. Without it,
the existing inventory remains unchanged. AMPS-authored model definitions are
software metadata, not downloaded observations or a permission exception for
third-party data. They record source references, mathematical form, input units,
assumptions, validity limitations, implementation identity and unavailable parts.
No missing measured value or source distribution is supplied as a default.

The selected release exposes definitions through optional `models()`/`model()`
Python/CLI metadata and a standard CSV table accessible by the existing C++
Catalogue. The runtime block/schema and old C++ ABI remain unchanged. Old
catalogues with no models still open; the method returns an empty collection.

New dependency-light shared C++ kernels (a new header, no existing rate-law
changes) provide explicit-parameter ion-mass balance, coherent radiative sums,
Opal energy marginal inversion, conservative two-body product kinematics,
inherit-parent-velocity/reservoir bookkeeping and fixed-site Polanyi-Wigner
finite-inventory loss. They choose no species/source, material, spectrum,
parameter, field or observation. The caller supplies consistent SI quantities,
state/energy reference and source/profile admission. Missing/invalid parameters
are typed errors; outputs remain unchanged on failure. Mathematical verification
of a kernel does not qualify its physical approximation or change M3 status.

## Independent references and checks

Use actual native byte/token/column/XML references for source reproduction;
closed-form identities/high-precision Decimal or rational arithmetic for shared
mathematics; conservation and CDF identities for event/sampling helpers. No AMPS
output is a physical truth. Verify domain/NaN/infinity/null-output and unchanged-
output failure controls, exact source roles/units, denied-source access, optional
old-catalogue compatibility and installed Python/C++ relocation. The normal
shared global suite discovers new administrative tests; actual-source classes
are outside the CORE protocol-only scope and remain honest SKIPs if absent.

Existing U/I IDs, thresholds, source selections, predecessors and hold-out rules
remain unchanged. No application build is required for header-only additions
unused by existing application code; compile actual new shared kernels plus the
ordinary shared C++ API/SDK and registered CORE case. No existing core numerical
source is modified. Preserve all existing-source test failures explicitly.

Artifacts include pre-change installation/source identities, exact commands,
source packets, recipes, publication/installation manifests, original-source and
cross-language results, failure logs, resource/time use and updated READMEs/
STATUS. READY denotes archive integrity, not physical qualification.
