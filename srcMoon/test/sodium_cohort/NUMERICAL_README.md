### Illuminated homogeneous event timing

The scorer compares the hexadecimal native `relative_event_time_s` for each
reacted parent with the independent high-precision root `-ln(U)/rate`. The
parent CSV still supplies the status of every original particle. Its displayed
time is an additional chronology check. Formatting a binary64 projection as
a decimal introduces two reporting differences that can exceed the error of
the native time.

`numerical.json` retains one `homogeneous_timing_breakdown` entry per launch.
Each entry gives the original parent ID at the maximum absolute value of each
component, its signed difference in seconds, and its absolute value divided
by the cohort horizon. The signed differences are telescoping **per parent**.
Different maxima can belong to different parents, so their sum is generally
different from the maximum total error.

| Component | Definition |
| --- | --- |
| Source clock rounding | Difference in first-hit time after independently rounding the exact optical depth to binary64 at the reference rate |
| Accepted rate effect | Difference when evaluating that rounded-depth root at the instantaneous native accepted rate |
| Native clock and transport remainder | Exact native time minus the rounded-depth root at the accepted rate; includes any difference between native libm and the correctly rounded reference and any local interval arithmetic |
| Parent binary64 projection | Binary64 parent time minus the more precise native time |
| Parent CSV text rendering | Exact decimal value of the CSV text minus the binary64 parent value |
