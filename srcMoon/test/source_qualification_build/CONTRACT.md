# Source-bound disposable Moon producer — before implementation

2026-11-19. The user authorized continued M3 implementation and the original-
research Na ground-ion profile/crosswalk. This helper stages an explicit
Na/NA_PLUS state mapping and builds only a caller-supplied disposable checkout
outside the active source tree. No particles, observations, calibration,
regression reference, physical error allowance or installed data lock changes.

Existing entry points: `state_profiles/compile_recipe/prepare.py::prepare`
authenticates the actual profile with the production native resolver, checks
source-SI charges through actual compiled expressions, and writes normal AMPS
input/companion/species files. `run_integration_tests.clean_configure_build`
removes build then runs normal Config.pl (TESTMODE off) and make-j16 with the
existing -O3/-g setting. `run_m3_development.normal_restore_evidence` binds
actual two successful commands, archive, executable, generated headers and
source-before/after hashes; file presence or a supplied PASS boolean is not proof.

Public inputs: explicit profile, mapping, disposable checkout, new output,
reference problem (normal-template or homogeneous-zero-acceleration), SPICE
paths and total wall allowance<=3600s. Exact compiled symbols are Na/NA_PLUS,
as in canonical input/species.input, mapped to23Na:ground/23Na+:ground.
No caller-specific model-error bounds are invented. Source/workflow identity
must match the active working production bytes before any configuration/build.
Active/nested/symlink-to-active checkout, stale/extra source, wrong mapping or
unrebased active-root site configuration is refused before mutation.

The public process never configures its active checkout. One supervised private
worker performs all recipe compilation, staging, clean configuration/build,
retention and authentic producer generation. A single CampaignBudget includes
setup/build/reporting,200GB memory ceiling,16allocated build cores and explicit
cleanup reserve. No per-child clock reset. Native build uses actual symbols and
generated records; unavailable states remainSKIPPED, build/identity/resource
failuresERROR. The helper never executes a particle cohort. Fresh output and all
failed logs/resource traces remain retained.

Output schema `srcMoon-actual-normal-restore-producer-v1` comes from the existing
proof function in the SAME private checkout after actual successful build.
Additional provenance pins the exact derived compile inputs, source mapping,
profile, recipe, source-SI charge interpretation and reference-problem choice.
This producer may support the existing explicit sodium-cohort wrapper, but
does not admit a physical channel or replace M0/convergence/formal prerequisites.

Protocol tests use labelled filesystem/source-identity/mapping fixtures only,
never fake physical profiles or success receipts. Actual-source recipe checks
and a later parent-authorized isolated native build provide the production path.
No permanent U/I ID is added. Source/data roadmap contracts remain unchanged.
# Conservative-product ABI requirement — 2026-11-19

The source-qualified product owner needs individual particle-weight correction
storage. This builder explicitly requests `packet_layout='conservative-products'`
from the normal compile recipe. It never patches generated headers or the core.
After the actual clean build, a guarded C++ preprocessor probe of the generated
`picGlobal.dfn` must prove `_INDIVIDUAL_PARTICLE_WEIGHT_MODE_` equals the defined
ON constant. Its command, logs and generated SHA are bound to the actual
producer receipt. Older source-compilation evidence without this proof remains
limited to its recorded layout and cannot imply product-execution readiness.
