# Reproducible I15 regional native-cell preparation

`prepare_i15_spatial_support.py` prepares complete explicitly selected native
D02 rectangles and their neighbour padding for I15's spatial comparison. It
reuses the committed signed-little-endian decoder, spherical stereographic
inverse and frozen production hashes from `prepare_d02_reference.py`.
It accepts no AMPS result or residual and never selects a region using model
agreement. This is reproducible spatial processing, not an epoch benchmark,
illumination validation, full-Moon area survey or D02 readiness promotion.

## Input contract and missing decisions

The required JSON schema is `srcMoon-I15-spatial-extraction-contract-v1`.
Its `status=APPROVED`, literal `frozen_before_model_evaluation=true`, and
`review` (`approved=true`, named `reviewer`, timezone-qualified `approved_utc`)
must describe an actual prior investigator decision. No approval or real
selection is generated by this script.

Other required fields are:

| Field | Meaning |
|---|---|
| `selection_model_independent`, `selection_basis` | Literal `true` and the declared basis for choosing native regions before model evaluation. |
| `area_measure` | Exactly `native-polar-stereographic-map-plane`; another convention remains SKIPPED until its physical transformation is specified and verified. |
| `time_support_id`, `time_support_provenance` | The supplied product-specific support identity and a path/SHA-256 record of its authoritative evidence. It is preserved, not derived from acquisition/creation dates. |
| `domains` | Nonempty explicit selected region records, defined below. |
| `timing_tolerances_s` | Optional previously documented event-ID/tolerance mapping, copied without alteration; absent timing tolerance remains unavailable to formal I15. |
| `logical_mapping_file` | Optional path/SHA-256 CSV containing `native_product_id,native_line,native_sample,logical_surface_element`; no nearest-cell or model-grid convention is guessed. |

Each region contains exact `native_product_id` (LPSR),
`visibility_product_id` (AVGVISIB), `source_id`, and positive integer
`line_min,line_max,sample_min,sample_max`. These bounds use native **one-based**
indices and include every selected cell, not a spacing subsample.
`scoring_line_min,scoring_line_max,scoring_sample_min,scoring_sample_max` specify
the predeclared scoring rectangle, with at least one complete native-cell
padding ring. Overlapping regions are ERROR, not silently deduplicated.
No real rectangle is supplied by default.

Relative evidence/mapping paths resolve against the input JSON. The public
CLI always enforces the committed production hashes. The Python-only hash
override exists for temporary toy-byte tests and is explicitly marked
`control_fixture_not_science` in provenance; it cannot qualify canonical data.

The user confirmed that additional D02 generation metadata are unavailable.
This processor does not invent the missing time-support contract. Missing
review, explicit area convention, source identity or temporal provenance
means SKIPPED before native decoding. Acquiring metadata and freezing real
regions are scientific prerequisites, not an excuse to select convenient
observations after seeing AMPS output.

## Quantities, units and frame

The exact native IMG/LBL pairs must match the frozen hashes and byte counts.
The loader verifies signed 16-bit little-endian representation, dimensionless
native values, planetocentric/east-positive DE421 mean-Earth/polar-axis frame,
spherical radii in km, metre/pixel scale and the supported pole-centred
projection. Each image's own scaling and offset control interpretation.

`reference_average_occurrence` comes only from AVGVISIB DN scaling;
`reference_psr` comes only from LPSR DN scaling. The retained raw DN columns,
product IDs, native indices and source locators preserve every conversion.
Coordinates are converted with the same independently documented native
projection implementation as the existing D02 processor. Source latitude
coverage is checked explicitly.

`pixel_area_m2` is **projected raster-cell area**, equal to the native map
scale squared. It is not true spherical lunar surface area. The convention
appears in every row and support/QA/provenance document. A physical-area
Jacobian or quadrature would need its own documented, independently verified
contract; none is silently added.

Eight-neighbour changes of native LPSR classes define the boundary ambiguity
flag. Only those boundary resolution cells carry their projected cell area
as `psr_resolution_allowance_m2`; other cells have zero. Native output rows
stay complete, including padding and flagged boundary rows. The formal I15
scorer independently checks coverage, edge definitions and allowance rather
than trusting a supplied total. Sparse probes cannot establish areas.

Unexpected native DN/coverage is preserved as
`quality=NATIVE_VALUE_UNINTERPRETED`, with raw DN retained and no invented
scientific value. The support remains PARTIAL and the processing result is
SKIPPED; neither a fill value nor its interpretation is guessed. A missing
logical mapping stays blank with `logical_mapping_status=UNAVAILABLE_NOT_ASSUMED`.
I20 must provide its separately qualified mapping before using those sites.

## Commands and artifacts

With an actual reviewed explicit-selection contract:

```bash
python3 -B srcMoon/test/data_processing/prepare_i15_spatial_support.py \
  --contract /absolute/path/to/reviewed_native_region_selection.json \
  --data-root /data/vtenishe/moon_validation_data \
  --output-dir "test_output/srcMoon/i15-spatial-$(date -u +%Y%m%dT%H%M%SZ)"
```

All output must be outside the canonical data tree and in a new/empty
directory. Canonical raw and processed data are read-only. No test figure is
created. Successful scoped processing writes:

* `site_reference.csv` — all selected native cells, raw/scaled quantities,
  coordinates, source identities, quality and optional logical mapping.
* `spatial_support.json` — exact regional/core bounds, explicit projected-area
  convention and time-support identity; READY applies only to spatial support.
* `provenance.json` — input/processor/raw/package/output hashes, native
  projection parameters, source locators and conversion/immutability records.
* `qa_report.json`, `result.json` — scoped status, real gaps, counts, missing
  logical mapping and separate `formal_i15_status=SKIPPED`.

This extraction cannot create the separate independent timestamped
`epoch_reference` or `timing_reference`, resolve exact-product averaging
settings, establish angular/sliver error, satisfy M1/I13 or validate the
illumination operator. A processing PASS never means formal I15 PASS.

The decoder/selection protocol tests run with:

```bash
python3 -B srcMoon/test/data_processing/test_i15_spatial_support.py
```

Seven tests use only temporary toy 5x5 images and metadata to verify native
endianness/scaling, coordinate conversion, boundary flags, missing decisions,
corrupt-byte refusal, preserved native gaps, complete padding/nonoverlap and
data/evidence immutability. Artificial bytes are explicitly labelled controls,
never archived observations or lunar model-validation evidence.
