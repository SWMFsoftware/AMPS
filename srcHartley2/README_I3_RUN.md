# How to build and run the 3I/ATLAS (I3) model

Step-by-step guide for the I3 cases of the generic comet application (`srcHartley2`): building the executable,
choosing a case, the chemical model and the brightness g-factor models, running, and finding the output.
Background and validation details are in [README.md](README.md), [i3/README.md](i3/README.md),
[CHEMISTRY.md](CHEMISTRY.md) and [CHEMISTRY_VARIANTS.md](CHEMISTRY_VARIANTS.md).

Keep this file current: any change to the comet model that affects how I3 is built, configured or run must
update this guide in the same change (rule in [README.md](README.md)).

Written 2026-11-21 for the working tree on top of commit `7c05480`, which includes the (not yet committed)
chemistry-variant implementation `OH_LOSS` (`CometChemistryVariants.*`).

## 1. The two input files

| File | Read | Owns | Change needs |
|---|---|---|---|
| `input/i3.conf` | at configuration/build time | species list (`H,H2,O,OH,H2O,CO,CO2`), DIM1 layout, block size, particle-buffer limits, collision topology, the compiled reaction table (`ChemistryReaction`, `ChemistryGroup`, `ChemistryRateTable` records) and its build-time constants | a clean rebuild |
| `input/i3.in` | at start-up (`-i`) | nucleus/domain and mesh, sources, run controls, chemistry switches and per-case rates, observation geometry, brightness (g-factor) models | no rebuild |

`input/i3.in` has a common block and six case blocks (`#begin case: N` ... `#end case`). It is generated by
`srcHartley2/i3/prepare_i3_cases.py` (section 6); edit it by hand only on purpose, and keep a frozen copy with
every run.

## 2. Build (once per code or `i3.conf` change)

All commands run from the AMPS repository root (the directory with `Config.pl`, `input/`, `srcHartley2/`).

```sh
./Config.pl -install            # only once for a fresh checkout
./Config.pl -application=i3     # selects input/i3.conf (there is no input/i3.input)
rm -rf -- build                 # always before a rebuild
make -j8 EXTRACOMPILEROPTIONS=-O3
sha256sum amps                  # record it with the run
```

On the Voyager cluster run `Config.pl` on the login node, but the `make` in a Slurm job on a compute node, e.g.
(the campaign scripts in `validation_runs/i3_master_campaign3_oxygen_20261119/scripts/build_i3.sbatch` do the same):

```sh
#!/bin/bash
#SBATCH --job-name=i3-build
#SBATCH --partition=normal128cores
#SBATCH --nodes=1 --ntasks=1 --cpus-per-task=32
#SBATCH --time=01:00:00
set -euo pipefail
cd /path/to/AMPS
rm -rf -- build
make -j32 EXTRACOMPILEROPTIONS=-O3
sha256sum amps
```

Rebuild after a change to source code or to `input/i3.conf` (including its reaction records and the build-time
constants of a `ChemistryRateTable`). Do **not** rebuild to change a case, a chemistry variant, a rate in
`i3.in` or a g-factor model: one executable serves all six cases.

Optional checks before a campaign:

```sh
srcHartley2/tests/run_all_stage_tests.sh        # portable regression suite (set TMPDIR to a shared,
                                                # executable directory on compute nodes: /tmp is noexec)
./amps --help                                    # usage, and the compiled chemistry groups and variants
```

Nightly regression test `i3` (details: [i3/README.md](i3/README.md), "Nightly regression test"): a test-mode build,
then two runs of case 1 from `input/i3-test.in`: `case1` with the default `STATE_RESOLVED` OH loss,
and `case1sa` with `--chemistry-variant OH_LOSS=SA1982_VH`. Each is compared with its references
for the number of MPI processes (18 outputs per layout):

```sh
./Config.pl -install -compiler=gfortran,gcc_mpicc   # once per checkout (writes Makefile.test from MakefileTest/Table)
make test_i3 MPIRUN="mpirun -np 4"                 # N = 4 or 8; on Voyager inside a Slurm job
cat test_i3.diff                                    # empty: passed ('test_i3[5].diff' on passion)
```

The passion/GNU `[5]` reference set was regenerated on 2026-11-22 from
`b4980503e35c498d42a689188e0f6fc2e4913d94`, including the DIM1 boundary callback fix.
It contains all 27 outputs for both four and eight MPI ranks, including `case1sa`.
Independent repeats reproduced all 54 files byte for byte and passed the normal
Table `DiffNum.pl` checks. Runtime inputs and comparison tolerances were unchanged.
The nightly entry now selects only `case1` and `case1sa`: 18 files per MPI layout,
or 36 references for four and eight ranks together. The case5 files from that
generation remain archived and are not selected by the reduced test.

`make test_i3` reconfigures the tree for the test-mode build (`-amps-test=on`, kept in `.amps.conf`) and moves
`amps` into `run_test_i3/`. Before a production run switch test mode off and repeat the clean build of section 2:
`./Config.pl -application=i3 -amps-test=off && rm -rf -- build && make -j8 EXTRACOMPILEROPTIONS=-O3`.

## 3. Choose a case

Every run needs `-i <file>` and, because `i3.in` has case blocks, an explicit `-case N`; an unknown case is fatal
and lists the available names.

| Case | Campaign phase | Observation start (UTC) | r_h [AU] | v_h [km/s] |
|---|---|---|---|---|
| 1 | Pre-Mars Closest Approach | 2025-09-28T17:45:26Z | 1.75 | -39.7 |
| 2 | Mars Closest Approach | 2025-10-03T00:06:41Z | 1.66 | -36.2 |
| 3 | Post-Mars Closest Approach | 2025-10-09T09:38:43Z | 1.54 | -29.6 |
| 4 | Pre-Perihelion | 2025-10-24T05:57:02Z | 1.36 | -5.8 |
| 5 | Perihelion | 2025-10-28T04:59:25Z | 1.36 | +0.4 |
| 6 | Post-Perihelion | 2025-11-01T04:03:41Z | 1.37 | +7.1 |

(v_h = `brightness.heliocentric_radial_velocity_km_s` of the case block; positive away from the Sun.)

Check a case (all model owners, no mesh or particle allocation):

```sh
mpiexec -n 2 ./amps -i input/i3.in -case 1 --validate-runtime-input     # prints PASS comet runtime input validation ...
```

## 4. Choose the chemical model

### 4.1 Switches in `i3.in`

| Key (common block, or a case block where noted) | Values | Meaning |
|---|---|---|
| `chemistry.enabled` | `true` | required by the compiled I3 network |
| `chemistry.residual_sampling` | `systematic` \| `bernoulli` | product-multiplicity sampling (command line: `--chemistry-residual-sampling`) |
| `chemistry.variant.OH_LOSS` (common or case block) | `STATE_RESOLVED` (default) \| `SA1982_VH` | which OH-loss model is active |
| `chemistry.table.OH_TAU_SA1982.file` | path | OH lifetime table for `SA1982_VH`; a relative path is resolved against the directory of the `.in` file |
| `chemistry.rate.<ID>_1au_s-1` (case block) | positive number | 1-AU rate of reaction `<ID>`; required for every reaction of an active variant and every ungrouped reaction; optional for inactive variants |

Other chemistry options on the command line: `--chemistry-estimator-mode configured|analog|enhanced` (Stage-9
estimator arms; see [CHEMISTRY.md](CHEMISTRY.md)).

### 4.2 The OH-loss variants (`OH_LOSS`)

- **`STATE_RESOLVED`** (default; all campaigns before 2026-11-21): OH -> O(3P) + H, O(1D) + H, O(1S) + H and OH
  photoionization, each with its own per-case rate a0 * F10.7P^n (from `i3/reference/photochemistry_channels.csv`)
  and excess energy, scaled by (1 AU / r_h)^2.
- **`SA1982_VH`**: one lumped OH -> O + H channel (excess energy 0.36 eV) plus OH ionization, with the
  heliocentric-velocity-dependent lifetime of the table file (Schleicher and A'Hearn 1982, legacy `OHPHOT` table):

  ```
  k_d(1 AU)   = 1/tau_fuv + 1/(S * OHTAUS(v_h))      k_ion(1 AU) = f_ion * k_d
  k(r_h)      = k(1 AU) * (1 AU / r_h)^2
  ```

  - OHTAUS is interpolated linearly in v_h on the -60...+60 km/s grid (2 km/s steps) and clamped outside it (the
    clamp is reported in the log and the output headers).
  - v_h is the case's `brightness.heliocentric_radial_velocity_km_s` (the same value the g-factors use).
  - tau_fuv (4.24e5 s) is in the table file: another solar-activity condition is another table file.
  - S and f_ion are build-time constants in `input/i3.conf`
    (`ChemistryRateTable=OH_TAU_SA1982 | MODEL=SA1982_OH_LIFETIME | SCALE_S=0.833e5 | ION_FRACTION=0.05`);
    changing them needs a rebuild. The reactions are `OH_O_H_SA1982` and `OH_ION_SA1982`.
  - The rates are per-case constants computed at start-up; no `chemistry.rate.*` records are needed for them.

### 4.3 How to select the variant

Precedence: **command line > case block > common block > compiled default** (`STATE_RESOLVED`).

```text
# in i3.in, common block (all cases) or inside one case block:
  chemistry.variant.OH_LOSS = SA1982_VH
  chemistry.table.OH_TAU_SA1982.file = oh_lifetime_sa1982.csv
```

```sh
# on the command line, for this run only (repeatable for further groups):
mpiexec -n 12 ./amps -i i3.in -case 3 --chemistry-variant OH_LOSS=SA1982_VH
```

The run log (`chemistry Chemistry.*` lines) and the brightness file headers (`DATASETAUXDATA Chemistry.*`) record
the effective variant, where it was selected, the table file and its SHA-256, and the derived rates.

A `channel-importance` policy (Stage 7) that does not match the active OH channels stops the run with an
explanation; see [CHEMISTRY_VARIANTS.md](CHEMISTRY_VARIANTS.md).

## 5. Choose the g-factor (brightness) models

Brightness is configured in `i3.in` only; there is no command-line switch for it. One record per emission:

```text
brightness.emission.<LABEL> = SPECIES | TRANSITION | MODEL or fixed g [s^-1] | G_PROVENANCE | THIN | ISOTROPIC_4PI |
                              TAU_MODE | CROSS_SECTION_M2 | TAU_FLAG_THRESHOLD | TAU_PROVENANCE [| EFFECTIVE_WAVELENGTH_NM]
```

Models available (field 3):

| Species | Model name | Needs in the case block / record |
|---|---|---|
| H Lyman-alpha | `H_LYA_IKL2020` | `brightness.solar_lya_flux_1au_photon_cm-2_s-1`; `TAU_MODE = LINE_CENTER` with a cross section and threshold |
| OH A-X (0-0) | `OH_AX00_SA1988_LOWELL_UNQUENCHED` (Schleicher and A'Hearn 1988) | the effective wavelength (field 11, e.g. 308.5 nm) |
| O I 130.4 nm | `O_I_1304_KVB2022_DIRECT_J2`, `O_I_1304_SUMER2001_DIRECT_J2` | `brightness.solar_oi1304_triplet_flux_1au_photon_cm-2_s-1` |
| O I 130.4 nm (Lyman-beta Bowen) | `O_I_1304_SUMER2001_LYB_BOWEN_J2` | `brightness.solar_lyb_flux_1au_photon_cm-2_s-1` |
| any | a positive number | a fixed photon g-factor in s^-1: no Doppler, distance or solar-activity scaling |

- The models are Doppler-dependent: they use the comet's v_h plus each particle's velocity projected on the
  solar direction. A velocity outside a model's published range is handled by `brightness.velocity_domain_policy`:
  `ABORT` (stop with the line, model and velocity) or `EXCLUDE_AND_REPORT` (omit and report the excluded fraction).
- Only `THIN` emission with `ISOTROPIC_4PI` is supported. For H, `LINE_CENTER` is mandatory (optical-depth flag
  only; the brightness is not attenuated).
- Several records for one species are allowed (the current `i3.in` has three O I records with different models);
  each gives its own set of columns in that species' brightness table.
- To switch a model: edit field 3 (and its provenance) in the record, then run `--validate-runtime-input`.
  Details, equations and references: README.md, section "DIM1 resonance-fluorescence brightness", and
  `src/models/resonance_fluorescence/`.

## 6. Regenerate `i3.in` (case generator)

```sh
python3 srcHartley2/i3/prepare_i3_cases.py [--output-directory DIR] \
    [--oh-loss state_resolved|sa1982_vh] [--oh-loss-case N=VARIANT ...] [--oh-lifetime-table FILE]
python3 srcHartley2/i3/prepare_i3_cases.py --help
```

It writes `i3.in` deterministically from `srcHartley2/i3/reference/` (cases, solar activity, photochemistry
channels, solar FUV lines). `--oh-loss` sets the variant of the common block, `--oh-loss-case` overrides it for
one case, `--oh-lifetime-table` names another lifetime table. The default output is `input/i3.in` (the
regression suite checks that file byte for byte).

## 7. Run one case

Freeze the executable and the exact inputs in a run directory before MPI starts (output goes to `PT/plots`
relative to the launch directory):

```sh
CASE=1
RUN="validation_runs/i3_case${CASE}_manual/production"
mkdir -p "$RUN"
cp -p amps input/i3.in input/i3.conf "$RUN/"
cp -p srcHartley2/i3/reference/oh_lifetime_sa1982.csv "$RUN/"     # needed for SA1982_VH
sed -i 's#^\(  chemistry.table.OH_TAU_SA1982.file = \).*#\1oh_lifetime_sa1982.csv#' "$RUN/i3.in"
( cd "$RUN" && set -o pipefail && \
  mpiexec -n 12 ./amps -i i3.in -case "$CASE" [--chemistry-variant OH_LOSS=SA1982_VH] 2>&1 | tee "case${CASE}.run.log" )
```

On Voyager, production cases run as Slurm jobs on one whole node, e.g.

```sh
sbatch --job-name=i3-case${CASE} --partition=superlong128cores --time=6-00:00:00 --ntasks=128 \
       --nodes=1 --exclusive --mem=0 --export=ALL,CASE=${CASE} production.sbatch
```

with a job script that freezes the inputs as above and runs `mpiexec -n $SLURM_NTASKS ./amps -i i3.in -case $CASE`
(template: `validation_runs/i3_master_campaign3_oxygen_20261119/scripts/production.sbatch`, which also checks the
executable's SHA-256 and refuses to reuse a run directory). The generated inputs request 200 brightness rays, a
10,000-iteration sampling window and at most 30,000 iterations.

## 8. Output and plots

- Radial profiles and brightness under `$RUN/PT/plots`:
  `pic.H.brightness.s=0.out=<k>.dat`, `pic.O.brightness.s=2.out=<k>.dat`, `pic.OH.brightness.s=3.out=<k>.dat`
  (one table per species; one column set per emission record). `out=0` exists only after the first complete
  sampling window.
- Compare with MAVEN/IUVS:

  ```sh
  python3 srcHartley2/visualization/plot_i3_brightness_comparison.py \
      "$RUN/PT/plots/pic.OH.brightness.s=3.out=0.dat" --no-show --output "$RUN/case${CASE}_OH_vs_IUVS.png"
  ```

- Edge correction and the collisionless reference: [EDGE_CORRECTION.md](EDGE_CORRECTION.md),
  [COLLISIONLESS_REFERENCE.md](COLLISIONLESS_REFERENCE.md); campaign interpretation: [i3/README.md](i3/README.md),
  [i3/COMPARISON.md](i3/COMPARISON.md).

## 9. Quick reference

```sh
./Config.pl -application=i3 && rm -rf -- build && make -j8 EXTRACOMPILEROPTIONS=-O3   # build
./amps --help                                                                          # options, chemistry variants
mpiexec -n 2 ./amps -i input/i3.in -case N --validate-runtime-input                    # check a case
mpiexec -n 12 ./amps -i i3.in -case N                                                  # run (default chemistry)
mpiexec -n 12 ./amps -i i3.in -case N --chemistry-variant OH_LOSS=SA1982_VH            # run with the SA1982 OH loss
```
